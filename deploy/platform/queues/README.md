Una instancia de API o worker declara la topología de forma idempotente. El exchange directo catalog.events enruta por tipo de evento. Las colas son durables/quorum. Los mensajes de retry vuelven por TTL de 5 s; se conservan messageId y headers. El ACK al mensaje original se hace después del write/confirm. reviews.dlq, catalog.changed.dlq y catalog.refresh.dlq conservan fallos de procesamiento. Los duplicados de reseñas se resuelven por _id = SKU:Idempotency-Key; un reintento del cliente debe reutilizar la clave. Si se reutiliza para contenido distinto prevalece el primer documento. El refresco de caché usa un worker; no aumentar sus réplicas sin deduplicar los refrescos entre consumidores.
